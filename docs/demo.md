# Демонстрация жюри за 5 минут

## Одна команда

После получения исходников, из корня проекта:

```powershell
npm run demo:up
```

Нужны только Docker Compose и Node.js 22+ с npm. Предварительный npm install не нужен:
демо-скрипты используют только стандартную библиотеку Node.
Первый build скачивает образ/зависимости и зависит от сети; следующие используют Docker cache.
Команда создаёт отсутствующий .env со случайными JWT keys, сохраняет существующий .env,
собирает образ, запускает PostgreSQL, применяет миграции, выполняет безопасный seed,
дожидается backend health и проходит полный flow через настоящий HTTP.
Не удаляет volumes и не очищает чужую БД.

Открыть http://localhost:3000/api/docs и http://localhost:3000/api/health/ready.
Если PORT изменён, используйте его. Для отдельного прогона уже запущенного окружения:

```powershell
npm run demo:flow
```

Отчёт artifacts/demo-flow.json содержит offerId, roundIds, purchaseId, сумму и пройденные этапы,
без паролей/JWT. Каждый прогон создаёт новый демонстрационный оффер и покупки, сохраняя аудит.
Для повторяемости новый оффер имеет PARTNER и ближайший срок окончания; он попадает в текущую
витрину. Если уже существующий оффер истекает менее чем через 30 секунд, дождитесь его окончания.

Скрипт предназначен только для локальной демонстрации; удалённые production URL отклоняются.
DEMO_BASE_URL задаёт другой локальный URL, PORT — порт по умолчанию.
SEED_DEMO_PASSWORD меняет пароль новых seed-пользователей; существующие пароли не сбрасываются.

## User stories и ручной сценарий

| Шаг | User story / действие                                                                        | Ожидаемый результат и бизнес-ценность                                |
| --- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 1   | Заказчик создаёт POST /offers                                                                | DRAFT; условия вводятся один раз                                     |
| 2   | Заказчик вызывает POST /offers/:id/submit                                                    | UNDER_REVIEW; снимок и раунд 1 зафиксированы                         |
| 3   | Product manager отправляет APPROVED с comment через POST /offers/:id/rounds/:roundId/reviews | PARTIALLY_APPROVED; две роли ещё ожидаются                           |
| 4   | Аналитик отправляет CHANGES_REQUESTED, operations — APPROVED                                 | CHANGES_REQUESTED; видно замечание и независимые решения             |
| 5   | Заказчик смотрит GET /offers/:id                                                             | currentRound, pendingRoles и launchBlockers объясняют запрет запуска |
| 6   | Заказчик PATCH /offers/:id меняет описание, затем submit                                     | Раунд 2, новый snapshot; старые решения сохранены                    |
| 7   | Три согласующих независимо отправляют APPROVED в раунд 2                                     | APPROVED, без последовательной цепочки                               |
| 8   | Заказчик POST /offers/:id/ready-to-launch                                                    | READY_TO_LAUNCH после финальных проверок                             |
| 9   | Клиент GET /storefront                                                                       | Оффер доступен среди максимум семи; «1% на всё» присутствует всегда  |
| 10  | Клиент дважды PUT /offers/:id/activation                                                     | Один и тот же activation.id, дубликатов нет                          |
| 11  | Клиент POST /purchases с amount=100.00, MCC=5411 и временем после активации                  | ACCRUED, cashback 10.00 при ставке 10%                               |
| 12  | Повторить тот же payload покупки с тем же reference                                          | Тот же purchase/evaluation/accrual; деньги не начисляются повторно   |
| 13  | Новая покупка с MCC=9999                                                                     | DECLINED, MCC_NOT_ELIGIBLE и понятное explanation                    |
| 14  | Заказчик GET /offers/:id/rounds и /history                                                   | Два раунда, замечания и исправления доступны для аудита              |

Для ввода полей используйте образец ниже. Даты замените на действующие UTC; для удобства
сначала можно выполнить автоматический flow и взять уже проверенные IDs из отчёта.

```json
{
  "title": "10% на продукты",
  "category": "Продукты",
  "type": "PARTNER",
  "cashbackPercent": "10.00",
  "startsAt": "ЗАМЕНИТЕ НА UTC В ПРОШЛОМ",
  "endsAt": "ЗАМЕНИТЕ НА UTC В БУДУЩЕМ",
  "payoutLimit": "100.00",
  "mccCodes": ["5411"],
  "clientDescription": "10% кэшбэка за продукты"
}
```

Автоматический сценарий подставляет реальные даты и IDs сам.
Покупка: offerId, уникальный reference, amount (decimal-строка), mcc, purchasedAt.
Витрина сортирует PARTNER сначала, затем по ближайшему endsAt и UUID, поэтому для ручного
свежего оффера выберите ближайшее будущее окончание относительно seeded-офферов.

## Короткая презентация

1. **30 секунд:** проблема банка — независимые согласования, потеря замечаний, риск двойных выплат.
2. **90 секунд:** в Swagger показать готовую карточку из artifacts/demo-flow.json,
   оба раунда и launchBlockers у seeded оффера CHANGES_REQUESTED.
3. **60 секунд:** клиентский storefront, активация и результат покупки с кэшбэком.
4. **60 секунд:** повтор покупки с тем же reference и отказ неверного MCC.
5. **30 секунд:** схема architecture.md, сценарная матрица testing.md, Docker health и CI workflow.

Это backend-демонстрация через API. Отдельного UI или реально подключённого банка нет.

## Если запуск не удался

- Docker Desktop должен быть запущен; порты 3000/5432 должны быть доступны.
- Существующий .env не перезаписывается. Если пароль БД менялся, старый volume продолжает
  использовать прежние credentials: верните соответствующие значения, не удаляйте данные автоматически.
- docker compose ps и docker compose logs --tail=100 backend показывают состояние.
- Если seed запускался давно и предложения истекли, demo:flow создаст новый действующий оффер.
- Не запускайте локальный Nest на том же HTTP-порту, что и Docker backend.
