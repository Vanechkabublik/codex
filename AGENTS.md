# Правила разработки

## Границы текущего этапа

Реализуется весь backend MVP: auth, workflow, витрина, покупки и начисления.
Не добавляйте фиктивные реализации вместо реальной логики и транзакций.
Доменная модель и этапы описаны в docs/architecture.md.

## Архитектура

- NestJS 11, строгий TypeScript. Не использовать any без обоснованной необходимости.
- Контроллеры отвечают за HTTP, сервисы за сценарии, entities за хранение. Не создавать god services.
- Разделять модули по доменным обязанностям. Не обращаться из контроллера напрямую к базе.
- Отдельные repositories/persistence вводить для сложных запросов и транзакционных сценариев, а не ради обёртки над каждым методом TypeORM.
- DTO с class-validator для body, query и path. Глобальный ValidationPipe: whitelist, forbidNonWhitelisted, transform. Явно преобразовывать числовые query-параметры.
- Общий prefix /api. Документировать endpoints и DTO через Swagger.
- Конфигурация через ConfigModule/ConfigService; проверять окружение при старте, не печатать секреты в ошибках.
- TypeORM подключать через forRootAsync. Runtime и CLI используют общие databaseOptions.
- synchronize и migrationsRun выключены. Схему изменять только проверенными миграциями; не изменять уже применённые миграции.
- Не коммитить .env, credentials, JWT secrets или пароли. .env.example содержит только локальные примеры.

## Домен

- Роли: OFFER_OWNER, PRODUCT_MANAGER, ANALYST, OPERATIONS_MANAGER, CLIENT, ADMIN.
- Статус оффера меняется только бизнес-сервисом; не принимать status из клиентского DTO.
- Согласование параллельное, по трём ролям; отдельная Review с обязательным комментарием. Не использовать три boolean-поля в Offer.
- Снимки раундов и предыдущие решения сохраняются. Редактирование не меняет старые снимки.
- Владение ресурсом проверять вместе с ролью; роль ADMIN не означает неявный обход всех правил.
- JWT access/refresh, ротация refresh-сессий и Argon2 реализуются в AuthModule.
- Денежные значения хранить в PostgreSQL numeric и обрабатывать decimal-арифметикой, не JavaScript floating point. Время — timestamptz UTC.
- Идемпотентность активации и начисления обеспечивать уникальными ограничениями БД.
- Расходование бюджета защищать транзакцией и блокировкой; предварительного чтения лимита недостаточно.
- Не добавлять новые бизнес-правила без явного указания допущения в документации.

## Проверки

- После изменений запускать npm run lint и npm run build; исправлять ошибки.
- Проверять сценарии и ограничения тестами по мере реализации бизнес-логики.
- Не заявлять о запуске Docker, миграций или тестов, если они не выполнялись.
